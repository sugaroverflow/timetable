## The policy (`apps/web/src/lib/csp.ts`)

Google's "strict CSP" shape: `script-src 'self' 'nonce-<fresh>'
'strict-dynamic'` with `https: 'unsafe-inline'` as pre-strict-dynamic
browser fallbacks (modern browsers ignore them). strict-dynamic is what
lets Clerk work unenumerated — its bundles are injected by scripts that
carry the nonce chain. The Clerk frontend-API origin for `connect-src`
is DECODED from `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` (the key is
`pk_*_` + base64 of the domain), so no per-environment hardcoding.
Styles stay `'unsafe-inline'` deliberately: inline style attributes are
idiomatic app-wide and in Clerk's widgets; the theme `<style>` tag's
values are already re-validated at the sink. Also: `object-src 'none'`,
`base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`,
Turnstile's frame for Clerk bot protection, dev-only `'unsafe-eval'`
(fast refresh) and `ws:` (dev overlay).

## Plumbing

The proxy's `routeRequest` mints the nonce and sends it two ways: the
`content-security-policy` REQUEST header is how Next learns to stamp its
own framework inline scripts, and `x-nonce` is how the root layout
stamps ours (the pre-paint theme script — RootLayout went async to read
`headers()`). Rewrites forward the modified request headers; redirects
skip CSP entirely (no document). The response carries the policy.
