## Code and docs that disagree

- **Key rotation needs Turn off, then Turn on.** The plan says that after
  losing a key "everyone would have to turn alerts on again". In the code,
  `turnOnPush` (`apps/web/src/lib/push.ts`) reuses the browser's existing
  subscription when there is one, and that subscription is still bound to
  the old public key. So once a device's row has been deleted after 20
  refused sends, Turn on re-posts the same dead subscription and the cycle
  repeats; and until then the line reads "Alerts are on". Turning off
  first (which unsubscribes the browser) fixes it. `docs/WEB_PUSH.md` §11
  and R19 document the behaviour; a code fix would compare
  `subscription.options.applicationServerKey` with `pushPublicKey` and
  resubscribe when they differ.
- **`PUSH_PAUSED` in the DO console.** The plan (§3.1) and the incident
  runbook's rate-limit lever describe a console env change as taking effect
  "on the component restart with no deploy". DigitalOcean applies a saved
  env change by redeploying the app with the new value, and the next
  spec deploy overwrites it with the GitHub variable. R19 says so and makes
  the GitHub variable the normal lever; the exact console behaviour is
  worth timing in step 8.
- **Plan vs build, already recorded in the FINALs:** `newMembers` fires on
  first login, not membership creation; Lounge chains follow the digest
  card; own-topic sessions don't push; unpublished topics' threads alert
  only host and admins; session times are Europe/London. WEB_PUSH.md
  describes the code.
