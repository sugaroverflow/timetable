# 2026-07-31 — Calendar v2: patterns, sessions, forum flag (closes #55)

The Phase 3 availability calendar shipped its backend in 2026-06 but was never
released (unlinked from nav, tracked as #55). This change finishes and
releases it, redesigned around three decisions from the 2026-07-30/31 design
conversation:

1. **Electors paint a weekly pattern, not slots.** The admin's schedule
   pattern IS the elector grid — availability resolves explicit per-slot
   answer → pattern cell → 🟡. New slots cost electors nothing; a college
   asks 2 cells, an unconference asks 16 hourly ones, with no granularity
   setting.
2. **The calendar coordinates; booking happens elsewhere.** Slots carry one
   topic + `empty → proposed → confirmed` + a URL pointing at the real event
   page. "Pencilled in", never "booked". Conflicts are conversations: the
   `slot_topics` m2m (and the dashboard conflicts table) died; a host can
   never displace another host's session.
3. **Everything behind a forum flag.** `settings.calendar.enabled` (default
   off) gates nav link, page, every query/mutation, and the ICS feed.
   Toggling off hides, never deletes.

## What changed

- **Schema (0024/0025):** `timeslots` + `status`/`topic_id`/`url`/
  `created_by_id`/`cell_key`; `slot_comments` + claim topic and frozen
  🟢🟡🔴 counts; new `availability_patterns` (jsonb cell map per
  forum+user); `slot_topics` dropped (existing tags carried into
  `timeslots.topic_id` as proposed).
- **Settings:** `calendar` group (enabled, confirmPolicy
  admins/hosts_propose/hosts_confirm, locations, patternCells, terms —
  zod-validated via `calendarSettingsSchema`) and
  `topics.hostsPublishDirectly` (hosts publish their own topics; review
  becomes post-hoc). First settings-dependent permissions in
  `shared/permissions.ts`.
- **API:** `calendar(includePast)` with pattern inference + avatar images;
  `myAvailabilityPattern` / `setMyAvailabilityPattern`; `createTimeslots`
  (idempotent bulk, replaces single/weekly-repeat mutations); `proposeSlot`
  (host off-piste, born proposed); `setSlotSession` (policy +
  never-displace gated); `addSlotComment(topicId?)` computes the snapshot
  server-side from the topic's hearters at post time — deliberately frozen,
  it records what the claim was based on. ICS maps proposed/confirmed →
  `STATUS:TENTATIVE`/`CONFIRMED`, carries `URL`, 404s while disabled.
- **Web:** `/f/[slug]/calendar` rebuilt as month-grouped rows (topic lens,
  status pills, avatar groups, own-availability control, discussion +
  session controls in an expander); `PatternGrid`, `CalendarSetup`
  (pattern×terms with a consequence-preview sentence; slots generated
  client-side on the admin's clock and stamped with `cellKey`),
  `ProposeSlotForm`, `CalendarSettingsForm` in Forum Settings; nav link
  gated on the flag. Old SlotCard/SlotAdminForm/SlotAdminControls/
  WeekdayPatternControl/SlotDiscussion deleted.
- **Digest:** "📅 Coming up" (confirmed, 14-day horizon, new-since-last-
  digest pills) and "Can you make it?" (proposed sessions for topics the
  recipient ❤️'d). Stale listings alone never trigger an email
  (`isForumDigestEmpty`).
- **Seeds:** fixture slots gained Status/Url, the seeded forum enables the
  calendar with a derived pattern + term, and two electors carry standing
  patterns so inference is visible on dev.

## Deliberately deferred

- Personal-calendar import (secret ICS URL → busy/free layer between
  explicit and pattern).
- A forum timezone setting (generation uses the admin's browser clock;
  digests format UTC).
- Activity-log coverage for slot actions; timeslot data in export/API page.
