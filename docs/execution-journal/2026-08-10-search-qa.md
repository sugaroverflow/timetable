# 2026-08-10 — Search QA round: fixed width, right side, match highlight

Ed's QA of the morning's search box, three items:

1. **No more grow-on-focus** — the pill resizing on focus read badly;
   the input is a fixed 140px now.
2. **Search sits right of the filters** (host filter, sort, then
   search).
3. **Matches highlight** via the CSS Custom Highlight API:
   `SearchHighlight` wraps the feed (display:contents), walks text nodes
   for the query, and registers ranges under
   `::highlight(topic-search)` (background `--primary-soft`, both
   themes). Chosen because it paints WITHOUT touching the DOM — topic
   bodies are markdown-rendered `dangerouslySetInnerHTML` where DOM
   patching fights React 19's re-apply (the CollapsibleTopicBody
   gotcha). A MutationObserver re-marks as infinite scroll appends;
   browsers without the API (old Firefox) just show no highlight.
   Verified live against dev's card DOM via console injection before
   committing (16 ranges, paints correctly in dark mode).

Round 2 (same day):

4. **Focus wash on the search box** — `.feed-search` is its own inner
   pill (constant padding so focusing never shifts layout);
   `:focus-within` washes it with `--ink` at 8%, theme-proof.
5. **The glass container is no longer card-coloured** — its glass now
   mixes from the PAGE background with 6% of the forum accent
   (`--primary`), so the pill reads as its own material against both
   the page and the cards passing behind it; the no-backdrop-filter
   fallback gets the same tint opaque. Per-forum themes tint their own
   pill automatically.
