# 2026-07-27 - Atom feed of published topics

## What happened

Agent-access roadmap phase 1 (per the API-page "Planned" list): each
publicly readable forum now serves an Atom feed at
`/api/timetables/<slug>/feed.atom` — the newest 50 published topics
with full sanitized-HTML bodies, author (host) names, published and
updated timestamps, and stable `urn:uuid:` entry ids that survive
renames. Forum pages advertise it via `<link rel="alternate"
type="application/atom+xml">` so feed readers autodiscover it; the API
page documents it (moved out of "Planned").

## Decisions

- **Atom over RSS 2.0**: unambiguous RFC 3339 dates and explicit
  content typing; every mainstream reader consumes both. Pure string
  builder in `apps/api/src/atom.ts` with escaping unit tests.
- **Anonymous-only**: the route always evaluates as a signed-out
  reader (feed readers carry no session), so private/deactivated
  forums 404. Authenticated feeds arrive with personal API tokens
  (roadmap phase 2).
- Entries reuse `buildFeed` (sort "newest") — same visibility rules as
  the app; `Cache-Control: max-age=300` keeps pollers off the hearts
  math.
- Topic links use the hostSlug-or-hostId permalink fallback; slug-less
  legacy topics link to the forum's All Topics page.
